# Asset integration

This repository does not store non-code assets. It fetches the pinned,
multi-license [`rumahl/assets`](https://github.com/rumahl/assets) repository and
copies the files the app needs into the frontend at build time.

## Layout

| Path | What it is |
| --- | --- |
| `upstream/` | Pinned checkout of `rumahl/assets`, generated by `scripts/fetch-assets.mjs` (gitignored) |
| `upstream.lock.json` | Pin: commit, archive URL and sha256 |

## How the build uses this

```
scripts/fetch-assets.mjs   rumahl/assets (pinned) -> assets/upstream/                  (gitignored)
scripts/sync-assets.mjs    assets/upstream/wallpapers/ -> frontend/packages/shell/src/assets/ (gitignored)
```

`sync-assets.mjs` holds an explicit list of `from -> to` rules; add a rule when
the app needs assets at a new location. Run the pipeline manually with:

```sh
pnpm --dir frontend assets:update
```

## Updating the upstream pin

1. Pick the commit you want from `rumahl/assets`.
2. Compute the archive checksum:

   ```sh
   curl -fsSL "https://github.com/rumahl/assets/archive/<commit>.tar.gz" | sha256sum
   ```

3. Update `commit`, `archive` and `sha256` in `upstream.lock.json`.
4. Run `node scripts/fetch-assets.mjs`.

A checksum mismatch is a hard error. GitHub generates archive tarballs on
demand, so their checksums are not a stable guarantee; if one changes, verify
the upstream commit before repinning.

### Environment switches

| Variable | Effect |
| --- | --- |
| `RUMAHL_ASSETS_OFFLINE=1` | Never download; use the existing `upstream/` if present. |
| `RUMAHL_ASSETS_FORCE=1` | Refetch even if the pin already matches. |
| `RUMAHL_ASSETS_STRICT=1` | Fail the build if download/extraction fails. |

## Adding an asset

Add it to [`rumahl/assets`](https://github.com/rumahl/assets) with a declared
license, then add a `from -> to` rule to `scripts/sync-assets.mjs` if the app
needs it at a new location.
